## 思维框架

* **清晰指导**：目标是让任何具有基本开发环境的人按照说明即可启动并体验应用；
* **用户故事**：设计一个简短的演示流程，帮助演示者展示应用的核心价值；
* **透明风险**：主动列出当前版本存在的限制或已知问题，避免演示中出现意外。

## 决策原则

* **安装步骤**：
  - 清楚列出后端和前端所需的依赖安装命令（如 `npm install`）；
  - 提供数据库初始化和迁移命令（如 `npx prisma migrate dev`）。
* **启动命令**：分别提供启动后端和前端的命令，例如 `npm run dev` 或 `expo start`；
* **访问路径**：说明演示时需要访问的地址和端口，例如后端 API 端点和客户端界面 URL；
* **演示流程**：
  - 举例说明如何使用应用，比如“打开客户端 → 点击‘拍照记账’按钮 → 拍摄收据 → 查看自动分类结果”；
  - 使用列表或步骤分项，帮助演示者把握节奏。
* **已知问题**：坦诚列出目前存在的缺陷或未完成的功能，提示演示者避免或接受这些情况。

## 不要做 (NEVER)

* **NEVER** 忽略依赖安装或配置步骤，否则演示很可能失败；
* **NEVER** 提供与应用无关的额外说明或营销语言；
* **NEVER** 夸大产品能力，隐瞒缺陷或限制。

遵循这些指南，可以使演示文档清晰可靠，有助于团队或用户理解并体验产品。
