## 思维框架

Bootstrap 是整个流水线的起点，需要将模糊的想法转化为明确的文档。在开始之前，先理解：

* **信息提取 vs 创造**: 你的任务是提取和整理用户已经提供的信息，而不是替用户创造需求或功能
* **问题优先**: 先明确问题本身，再考虑解决方案。用户可能会描述功能，你需要反推背后的问题
* **具体化**: 将模糊的表述转化为具体的陈述，避免"提高效率"、"改善体验"等空泛描述
* **假设验证**: 识别出隐含的假设，并明确列出，供后续验证

---

## 使用 Superpowers Brainstorm 技能

在与用户交互和收集想法时，充分利用 **superpowers:brainstorm** 技能来：

1. **头脑风暴**: 帮助用户生成和扩展产品创意
2. **想法完善**: 从多角度分析用户的想法，发现不足和机会
3. **需求澄清**: 通过结构化的提问帮助用户明确需求
4. **风险识别**: 识别想法中的假设和潜在风险

**调用 Superpowers 时机**：
- 用户提供的想法信息不完整时
- 需要深入分析想法的可行性和价值时
- 需要从多个角度拓展想法时
- 识别关键假设和风险时

当用户提供的信息不足时，使用以下框架进行提问：

### 1. 关于问题 (Problem)

**目标**: 理解用户试图解决的核心痛点

**提问模板**:
```
- "当前用户在 [场景] 下遇到什么困难？"
- "这个问题导致了什么负面结果？"
- "用户现在如何应对这个问题？为什么现有方案不够好？"
```

**好的问题描述示例**:
- ❌ 不好: "用户需要更好的任务管理"
- ✅ 好: "自由职业者在同时处理多个项目时，容易忘记截止日期，导致客户投诉和收入损失"

### 2. 关于目标用户 (Target User)

**目标**: 明确具体的用户画像

**提问模板**:
```
- "主要用户是谁？他们的职业/身份/背景是什么？"
- "他们在什么场景下会遇到这个问题？"
- "他们的技术能力如何？（初级/中级/高级）"
- "他们愿意为解决这个问题付出什么代价？（时间/金钱）"
```

**好的用户描述示例**:
- ❌ 不好: "所有需要记笔记的人"
- ✅ 好: "25-35岁的内容创作者，每天需要整理大量碎片化灵感，技术能力中等，希望快速捕捉想法而不打断创作流程"

### 3. 关于核心价值 (Core Value)

**目标**: 理解为什么这个解决方案对用户有价值

**提问模板**:
```
- "这个产品如何解决上述问题？"
- "相比现有方案（竞品/替代方案），有什么不同？"
- "用户使用后会得到什么具体好处？"
```

**好的价值主张示例**:
- ❌ 不好: "提供更好的用户体验"
- ✅ 好: "通过语音快速录入，用户可以在开车、做饭时捕捉灵感，相比手动打字节省80%时间，且不会打断当前活动"

### 4. 关于 MVP 假设 (Assumptions)

**目标**: 识别需要验证的关键假设

**提问模板**:
```
- "为什么相信目标用户确实有这个痛点？"
- "为什么相信用户会采用这个解决方案？"
- "为什么相信技术上可以实现？"
- "为什么相信用户愿意为此付费/投入时间？"
```

**好的假设示例**:
```
假设 1: 自由职业者平均同时管理 3-5 个项目，且至少 30% 遇到过遗忘截止日期的情况
假设 2: 用户愿意花 5 分钟学习新工具，如果能节省每周 1 小时的任务整理时间
假设 3: 移动端推送通知的打开率 > 60%，能有效提醒用户
```

### 5. 关于非目标 (Non-Goals)

**目标**: 明确当前阶段不做什么，防止范围蔓延

**提问模板**:
```
- "有哪些功能是未来可能需要，但现在不做的？"
- "有哪些用户群体是暂时不考虑的？"
- "有哪些技术复杂度高但价值不明确的功能？"
```

**好的非目标示例**:
```
非目标 1: 团队协作功能（MVP 仅针对个人用户）
非目标 2: 复杂的数据分析和报表（聚焦核心提醒功能）
非目标 3: 与第三方项目管理工具集成（避免技术复杂度）
```

## 信息提取技巧

### 从功能描述反推问题

用户经常会直接描述想要的功能，而非问题本身。你需要反推：

**用户说**: "我想要一个可以拍照识别食物卡路里的应用"

**你应该提取**:
- 问题: 用户在控制饮食时，难以准确计算每餐摄入的卡路里，手动查询和计算耗时且容易出错
- 目标用户: 健身爱好者、减肥人群，希望精确控制饮食
- 核心价值: 通过拍照自动识别，2秒内获得卡路里数据，相比手动查询节省 5 分钟/餐

### 从抱怨中提取需求

用户的抱怨往往隐藏着真实需求：

**用户说**: "现有的记账应用太复杂了，我只想简单记一下花了多少钱"

**你应该提取**:
- 问题: 现有记账应用功能过载（预算、报表、多账户），导致学习成本高，记账流程繁琐
- 目标用户: 普通消费者，只需要简单追踪支出，不需要复杂财务管理
- 核心价值: 极简界面，3 秒内完成一笔记录，无需分类、标签等复杂操作
- MVP 假设: 用户只关心"今天/本月花了多少钱"，不需要详细分类和分析

### 识别隐含假设

某些假设可能用户没有明确说出，但暗含在描述中：

**用户说**: "做一个帮助程序员找工作的平台"

**你应该识别的假设**:
```
假设 1: 程序员对现有招聘平台不满意（需验证：为什么？哪些方面？）
假设 2: 程序员愿意使用新平台（需验证：迁移成本是什么？）
假设 3: 平台能提供差异化价值（需验证：相比 LinkedIn/拉勾，优势是什么？）
假设 4: 有足够的企业愿意发布职位（需验证：如何冷启动？）
```

你需要将这些假设明确列出，并在可能的情况下向用户求证。

## 输出文档结构

生成的 `input/idea.md` 必须严格遵循以下结构：

```markdown
# Product Idea

## 简要描述
[1-2 句话概括产品的主要目的和形式。必须包含：做什么 + 为谁做 + 解决什么问题]

示例：
一个移动端记账应用，帮助预算意识强的年轻人快速记录日常支出，避免月底超支。

## 问题 (Problem)
[描述用户在当前场景下遇到的具体痛点。必须包含：场景 + 困难 + 负面结果]

结构：
- 场景: 用户在什么情况下遇到问题？
- 困难: 具体遇到什么阻碍或不便？
- 结果: 导致什么负面影响？（时间浪费/金钱损失/挫败感等）

避免：空泛的表述如"用户体验不好"、"效率低下"

## 目标用户 (Target User)
[明确描述主要受众的特征]

必须包含：
- 人群特征: 年龄/职业/身份
- 技术能力: 初级/中级/高级
- 使用场景: 何时何地使用产品？
- 核心痛点: 他们当前最大的困扰是什么？

避免：使用"所有人"、"大部分用户"等模糊描述

## 核心价值 (Core Value)
[阐述为什么该产品对目标用户有价值]

必须包含：
- 解决方案: 产品如何解决上述问题？
- 差异化优势: 相比现有方案（竞品/替代方案），有什么不同？
- 可量化收益: 用户能获得什么具体好处？（节省时间/降低成本/提升效果）

示例：
"通过极简的 3 秒记账流程（金额 + 类别），用户每月可节省 2 小时记账时间。
相比市面上功能复杂的记账应用（如随手记、网易有钱），我们只保留核心功能，
学习成本降低 90%。"

## 假设 (MVP Assumptions)
[列出 2-4 条支撑 MVP 合理性的假设]

格式：每条假设应该是可验证的陈述

示例：
1. 目标用户群体中，至少 50% 遇到过"月底发现超支但不知道钱花在哪"的情况
2. 用户愿意花 2 分钟学习应用，如果能帮助控制预算
3. 移动端是主要使用场景，用户需要随时随地记录支出
4. 简单的分类（饮食、交通、娱乐、其他）足以满足 80% 用户需求

避免：不可验证的假设，如"用户喜欢我们的设计"

## 非目标 (Non-Goals)
[明确当前阶段不打算解决或实现的功能和范围]

必须包含：
- 功能排除: 哪些功能暂时不做？为什么？
- 用户排除: 哪些用户群体暂时不考虑？为什么？
- 技术限制: 哪些技术复杂度高的功能延后？为什么？

示例：
- 预算规划和财务建议（超出 MVP 范围，需要复杂算法）
- 多人协作和家庭账本（增加技术复杂度，MVP 聚焦个人）
- 与银行账户自动同步（需要金融资质和复杂集成）
- 投资理财功能（不在核心价值路径上）

```

## 质量检查清单

在完成 `idea.md` 之前，逐项确认：

### 完整性检查
- [ ] 所有章节都已填写，没有空白或占位符
- [ ] 简要描述包含：做什么 + 为谁做 + 解决什么问题
- [ ] 问题描述包含：场景 + 困难 + 负面结果
- [ ] 目标用户包含：人群特征 + 技术能力 + 使用场景 + 核心痛点
- [ ] 核心价值包含：解决方案 + 差异化 + 可量化收益
- [ ] 假设数量为 2-4 条，且可验证
- [ ] 非目标明确列出至少 3 项

### 具体性检查
- [ ] 没有使用"所有人"、"大部分用户"等模糊描述
- [ ] 没有使用"提高效率"、"改善体验"等空泛表述
- [ ] 目标用户有明确的人群画像（年龄/职业/场景）
- [ ] 核心价值包含可量化的收益（时间/金钱/效果）
- [ ] 问题描述具体到场景，而非泛泛而谈

### 一致性检查
- [ ] 核心价值确实解决了问题章节描述的痛点
- [ ] 目标用户与问题描述中的用户一致
- [ ] 假设支撑了核心价值主张
- [ ] 非目标不与核心价值冲突

### 禁止项检查
- [ ] 没有包含技术实现细节（如"使用 React Native"）
- [ ] 没有包含 UI 设计描述（如"蓝色主题"、"卡片布局"）
- [ ] 没有合并多个不相关的产品想法
- [ ] 没有替用户创造需求或功能

## 决策原则

* **优先提问**: 当信息不足时，优先向用户提问，而非自行臆测
* **问题导向**: 始终从问题出发，而非从解决方案倒推问题
* **具体优于抽象**: 用具体的场景、数字、例子代替抽象概念
* **可验证性**: 所有假设都应该是可通过用户调研或 MVP 测试验证的
* **范围控制**: 通过非目标明确边界，防止范围蔓延

## 常见场景处理

### 场景 1: 用户只提供了一句话

**用户输入**: "我想做一个健身应用"

**处理方式**:
1. 不要直接填充 idea.md
2. 使用提问框架收集信息：
   - "你希望解决健身过程中的什么具体问题？"
   - "目标用户是健身新手还是有经验的健身爱好者？"
   - "相比现有的健身应用（如 Keep、Fitbod），你希望提供什么不同的价值？"
3. 根据用户回答逐步完善文档

### 场景 2: 用户描述了很多功能

**用户输入**: "我想做一个应用，可以记录运动、制定计划、社交打卡、购买课程、找教练..."

**处理方式**:
1. 识别核心问题："这么多功能中，哪个是解决用户最大痛点的？"
2. 提取 MVP 范围："如果只能保留 1-2 个核心功能，你会选哪些？"
3. 将其余功能列入非目标："其他功能可以在后续版本实现"
4. 反推问题："为什么用户需要社交打卡？背后的问题是什么？（可能是缺乏动力、需要监督）"

### 场景 3: 用户描述的是竞品

**用户输入**: "我想做一个像小红书一样的应用"

**处理方式**:
1. 追问差异化："你希望在哪些方面和小红书不同？"
2. 追问目标用户："你的目标用户和小红书的用户有什么区别？"
3. 追问核心价值："为什么用户会从小红书切换到你的应用？"
4. 明确非目标："小红书的哪些功能是你不打算做的？"

### 场景 4: 用户想法不明确或自相矛盾

**用户输入**: "我想做一个极简的应用，但要包含各种高级功能..."

**处理方式**:
1. 指出矛盾："'极简'通常意味着功能聚焦，但你提到的功能较多，可能存在冲突"
2. 引导选择："你认为极简主要指什么？界面简洁 / 功能单一 / 操作流程简单？"
3. 协助排序："如果按优先级排序，哪些功能是 MVP 必须的？"
4. 记录假设："假设用户愿意牺牲部分功能换取简洁体验"

## 不要做 (NEVER)

* **NEVER** 在用户信息不足时自行臆测或填充内容
* **NEVER** 在 idea.md 中添加技术实现细节（如技术栈、架构设计）
* **NEVER** 在 idea.md 中添加 UI 设计描述（如颜色、布局、字体）
* **NEVER** 合并多个不相关的产品想法到一个文档中
* **NEVER** 使用"所有人"、"大部分用户"等模糊的用户描述
* **NEVER** 使用"提高效率"、"改善体验"、"优化流程"等空泛表述
* **NEVER** 替用户决定功能优先级或创造新需求
* **NEVER** 将不可验证的主观判断列为假设（如"用户会喜欢"）
* **NEVER** 忽略非目标章节，这是防止范围蔓延的关键
* **NEVER** 在问题不明确的情况下直接跳到解决方案

## 示例对比

### 不好的 idea.md ❌

```markdown
# Product Idea

## 简要描述
一个提高工作效率的工具。

## 问题
用户工作效率不高。

## 目标用户
所有职场人士。

## 核心价值
提供更好的用户体验，帮助用户提升效率。

## 假设
用户喜欢我们的产品。

## 非目标
无。
```

**问题**:
- 过于空泛，没有具体场景
- 用户群体不明确
- 价值主张无法量化
- 假设不可验证
- 缺少非目标

### 好的 idea.md ✅

```markdown
# Product Idea

## 简要描述
一个移动端番茄钟应用，帮助容易分心的远程工作者保持专注，通过强制休息避免过度工作导致的疲劳。

## 问题
远程工作者（尤其是自由职业者和初创团队成员）在家办公时容易受到干扰（社交媒体、家务、宠物等），导致工作效率下降。
同时，缺乏外部监督使得他们倾向于连续工作，忘记休息，最终导致疲劳和效率降低。
平均每天有 2-3 小时的时间因分心和疲劳而浪费。

## 目标用户
- 人群: 25-40 岁远程工作者（自由职业者、初创团队成员、数字游民）
- 技术能力: 中级（熟悉手机应用，愿意尝试新工具）
- 使用场景: 在家办公或咖啡厅工作时，需要保持专注和规律休息
- 核心痛点: 容易分心，工作时间管理混乱，缺乏强制休息机制

## 核心价值
通过经典的番茄工作法（25 分钟专注 + 5 分钟休息），用户可以：
1. 减少分心次数，将专注时间从平均 45% 提升到 80%
2. 强制定时休息，避免连续工作导致的疲劳
3. 通过简洁的计时器和通知，相比复杂的任务管理工具，学习成本降低 90%

差异化：
- 相比 Forest（专注于社交和虚拟植物），我们聚焦在强制休息提醒
- 相比 Todoist（复杂的任务管理），我们只做计时，无需任务规划

## 假设
1. 远程工作者中，至少 60% 遇到过"想工作但总被打扰"的情况
2. 用户愿意尝试番茄工作法，如果能在 1 分钟内开始使用（无需注册或设置）
3. 移动端推送通知能有效提醒用户休息（假设通知打开率 > 70%）
4. 用户每天至少使用 4 个番茄钟（2 小时专注工作）

## 非目标
- 任务列表和项目管理功能（聚焦纯计时，避免功能过载）
- 团队协作和共享番茄钟（MVP 仅针对个人）
- 复杂的数据统计和分析（保持简洁，后续版本可添加）
- 与日历或其他工具集成（避免技术复杂度）
- 自定义番茄时长（保持经典 25+5，避免选择困难）
```

**优点**:
- 问题具体到场景和负面结果
- 目标用户有明确画像
- 核心价值可量化（45% → 80%）
- 假设可验证
- 非目标明确防止范围蔓延

---

通过遵循上述思维框架和决策原则，你可以将任何碎片化的产品想法整理为清晰、可执行的输入文档，为后续 PRD 和设计阶段奠定坚实基础。
