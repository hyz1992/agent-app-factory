# 上下文隔离策略

## 目的

确保每个 Agent 只依赖文件输入，不依赖对话上下文，从而：
- 支持分会话执行，节省 Token
- 保证可恢复性和可重现性
- 兼容所有 AI 助手（Claude Code、OpenCode 等）

## 强制规则

所有 Agent 在执行时必须遵循以下规则：

### 1. 输入来源限制

* **ONLY** 从 `pipeline.yaml` 中定义的 `inputs` 文件读取信息
* **NEVER** 使用对话历史中"记忆"的内容
* **NEVER** 假设自己知道之前阶段发生了什么

### 2. 独立执行假设

每个 Agent 应假设：
- 这是一个全新的会话
- 对之前阶段的执行过程一无所知
- 唯一的信息来源是指定的输入文件

### 3. 调度器责任

调度器在激活每个 Agent 前，必须：
1. 明确告知该阶段的输入文件列表
2. 明确告知该阶段的输出文件列表
3. 提醒 Agent 遵循上下文隔离规则

## 检查清单

Agent 执行前的自检：

- [ ] 我只从指定的输入文件读取信息
- [ ] 我没有使用对话历史中的任何假设
- [ ] 如果输入文件缺失，我会报错而非猜测内容
- [ ] 我的输出只写入授权的目录

## 示例

### ❌ 错误做法

```
用户之前说想做一个记账应用，所以我直接开始设计...
```

### ✅ 正确做法

```
让我先读取 artifacts/prd/prd.md 了解产品需求...
[读取文件]
根据 PRD 中定义的需求，我开始设计...
```

## 违规处理

如果发现 Agent 违反上下文隔离规则（例如使用了未在输入列表中的信息），调度器应：
1. 标记该阶段产物为不可信
2. 要求 Agent 仅基于输入文件重新执行
